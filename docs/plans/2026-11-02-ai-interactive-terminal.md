# AI 交互模式：在终端里执行命令

> 写于 2026-11-02，基于 v0.11.5（`b95e856`）。状态：**第一、二阶段已完成**（见 docs/STATUS.md 第三十五、三十六节），第三阶段待做。三个待定事项都按建议执行：执行期间暂停键盘输入；完全放行模式下高危命令仍要确认；分页自动按空格翻页。

## 一、要解决的问题

现在 AI 执行命令（`run_command`）时，会在同一条 SSH 连接上另开一个 exec 通道，执行完一条命令就关掉（`ai/tools.rs` → `ssh::exec_command`）。这种方式对 Linux 服务器很合适，但对交换机基本不可用：

| 问题 | 原因 |
|---|---|
| H3C、华为等设备经常拒绝或只部分支持 exec 通道 | 设备只实现了交互式 shell |
| `system-view` → `interface …` 这样的配置视图无法保持 | 每条命令都在一个新通道里执行，状态不保留 |
| `---- More ----` 分页卡住，60 秒后超时 | 非交互方式没法按空格翻页 |
| `[Y/N]` 确认、密码提示也会卡住 | 同上 |
| **Telnet、串口、本地终端里 AI 完全不能用** | `ai_send` 只在 `state.ssh` 里查找会话 |
| `read_terminal` 读到的是旧内容 | `terminal_tail` 是这一轮对话开始时拍下的快照，之后不再更新 |

## 二、思路

新增一个工具 `type_in_terminal`：**把命令直接输入到用户当前的终端里**，就像用户自己打字一样，然后读取设备的回显，直到出现提示符为止。遇到分页时自动翻页，遇到需要人回答的提示时停下来交给用户。

保留现有的 `run_command`。两个工具分工：

| | `run_command`（非交互） | `type_in_terminal`（交互，新增） |
|---|---|---|
| 适用场景 | Linux 服务器上的查询和脚本 | 交换机、路由器，以及需要保持状态的操作（`su`、配置视图） |
| 支持的会话 | 仅 SSH | SSH、Telnet、串口、本地终端 |
| 用户屏幕 | 不受影响 | 命令和输出都显示在终端里（也会被录制） |
| 状态 | 每条命令都从头开始 | 和用户共用同一个会话的状态 |

模型怎么选：系统提示词里写明规则。Telnet、串口、本地终端只提供 `type_in_terminal`；SSH 会话两个都提供，网络设备优先用交互方式。

## 三、`type_in_terminal` 的行为

### 参数

```json
{
  "command": "display interface brief",   // 要输入的一行命令
  "timeout_secs": 30                      // 可选，默认 30，最多 300
}
```

另有一个配套工具 `terminal_key`，只能发送一组固定的按键：`ctrl_c`、`enter`、`space`、`q`、`y`、`n`。用来回答 `[Y/N]` 或者中断一条卡住的命令。**不提供发送任意文本的能力**，所以 AI 没法输入密码。

### 执行过程

1. **执行前检查**：如果当前屏幕最后一行是密码提示（`Password:`、`密码:` 等），拒绝执行，并告诉模型“需要用户先输入密码”。
2. **记下当前提示符**：取屏幕最后一行，例如 `<core-sw01>`。
3. **输入命令**：写入 `command + "\r"`，和用户按回车完全一样。
4. **收集输出**：通过一个实时“输出分流口”（tap）接收这个会话的所有输出，直到满足下面任一条件：

| 结束条件 | 判断方式 | 返回的 `ended_by` |
|---|---|---|
| 出现提示符 | 最后一行匹配提示符规则（见下表） | `prompt` |
| 需要人回答 | 最后一行像 `[Y/N]:`、`Password:`、`(yes/no)?` | `input_required` |
| 长时间没有输出 | 超过 2 秒没有新数据，且最后一行不像提示符 | `idle` |
| 超时 | 超过 `timeout_secs` | `timeout`（不会自动中断，由模型决定要不要发 `ctrl_c`） |

5. **自动翻页**：最后一行出现 `---- More ----`、`--More--`、`-- More --`、`<--- More --->` 时，自动发送一个空格。最多翻 500 页，输出总量超过 30KB 时发送 `ctrl_c` 停止，并标记 `truncated`。
6. **整理输出**：去掉 ANSI 转义序列；去掉分页提示，以及设备用来擦除分页提示的退格和光标左移序列；处理 `\r`；去掉回显的命令行和最后的提示符；最后再过滤一遍私钥块（沿用 `redact_private_keys`）。

返回给模型的内容：

```json
{ "output": "...", "prompt": "[core-sw01-GigabitEthernet1/0/1]", "ended_by": "prompt", "truncated": false }
```

返回提示符，是为了让模型知道自己现在处在哪个视图里。

### 提示符规则

| 设备 | 示例 |
|---|---|
| H3C / 华为（用户视图） | `<core-sw01>` |
| H3C / 华为（系统视图、接口视图） | `[core-sw01]`、`[core-sw01-GigabitEthernet1/0/1]` |
| 思科、锐捷、中兴 | `core-sw01>`、`core-sw01#`、`core-sw01(config-if)#` |
| Linux | `user@host:~$`、`root@host:/etc#`、`[root@host ~]#` |

为了避免把输出中间的某一行误判成提示符，只有当这一行是**输出的最后一行，后面没有换行，并且 300ms 内没有新数据**时，才判定为提示符。

## 四、实现

### 后端

1. **输出分流口（tap）**：参照现有的录制槽（`recorder` slot），给 SSH 的 `LiveSession` 和 `direct.rs` 的三种会话各加一个 `tap: Mutex<Option<mpsc::UnboundedSender<Vec<u8>>>>`。读线程每读到一块数据，就复制一份发给 tap。同一时间只允许一个 tap。
2. **统一的会话句柄**：新增 `enum TerminalTarget { Ssh(Arc<LiveSession>), Direct(Arc<DirectSession>) }`，提供 `write`、`tap`、`tail` 三个方法。`ToolContext.session` 改为 `Option<TerminalTarget>`。
3. **`ai_send`**：会话 id 先在 `state.ssh` 里查，查不到再到 `state.direct` 里查。非 SSH 会话不提供文件类工具，因为那些工具依赖 SFTP。
4. **`read_terminal` 改为实时读取**：在调用时读取会话当前的输出尾部，而不是用这一轮开始时的快照。
5. **新模块 `ai/interactive.rs`**：放提示符识别、分页处理、输出整理、结束条件判断这几个纯函数（便于单元测试），以及 `type_in_terminal` 和 `terminal_key` 的执行逻辑。
6. **权限**：两个新工具都归为“会改变状态”的工具，`Manual` 和 `Auto` 模式下都要用户确认。另外有一份**高危命令清单**（`reboot`、`reset saved-configuration`、`format`、`delete`、`undo` 加关键配置、`write erase`、`rm -rf` 等），**即使在 `Bypass` 模式下也必须确认**。
7. **系统提示词**：补充两种工具的选择规则；说明遇到 `input_required` 时要向用户说明情况，不要自己猜答案；不要关闭分页，loki 会自动翻页；说明当前会话的协议，以及主机名里的厂商信息（例如扫描添加的 `H3C-10.0.8.1`）。

### 前端

1. **终端横幅**：AI 输入命令期间，终端顶部显示“AI 正在执行：display interface brief”，旁边有一个 **停止** 按钮，点击后发送 Ctrl+C 并结束这次调用。
2. **执行期间暂时屏蔽用户输入**，避免用户的按键和 AI 的命令混在一起。横幅上注明“此时键盘输入已暂停”。
3. **确认卡片**：标题为“在终端中输入”，显示命令内容和目标主机；高危命令用红色标出。
4. **工具卡片**：显示整理后的输出和结束方式（例如“已到提示符” / “等待你输入” / “超时”）。
5. **mock**：在 `dev/mock-ipc.js` 里模拟一台 H3C，包含分页、`[Y/N]` 确认和视图切换，方便开发时调试界面。

## 五、测试

- **提示符识别**：上表中的每种设备，加上一组不应被识别为提示符的输出行（例如 `Interface  PHY  Protocol`）。
- **分页**：模拟设备分三页输出，并带退格擦除序列；验证自动翻了 2 次页、拼起来的输出完整、没有残留的 `More`。
- **结束条件**：提示符、`[Y/N]`、密码提示、长时间无输出、超时，各一个测试。
- **端到端**：参照 `direct.rs` 里新加的 Telnet 测试，起一个本地假设备：会回显、会分页、会切换视图。从 `type_in_terminal` 一路测到返回结果。
- **安全**：屏幕上是密码提示时拒绝执行；`terminal_key` 不接受清单以外的按键；高危命令在 `Bypass` 模式下仍然要求确认；输出里的私钥会被过滤掉。

## 六、分阶段

| 阶段 | 内容 | 完成后的效果 |
|---|---|---|
| **一** | tap、`type_in_terminal`、`terminal_key`、输出整理、提示符和分页处理、实时 `read_terminal`、终端横幅和确认卡片，先只支持 SSH 会话 | SSH 连接的交换机上，AI 可以进入配置视图、执行命令、自动翻页 |
| **二** | `TerminalTarget` 统一句柄，`ai_send` 支持 Telnet、串口、本地终端会话，按会话类型过滤工具 | Telnet 交换机和串口控制台上也能用 AI |
| **三** | 高危命令清单、系统提示词里加入厂商信息、确认卡片上的高危标记 | 更安全，模型对设备也更了解 |

以后可以在这个基础上做“批量执行”：对扫描添加的一组交换机依次运行同一组命令，并汇总结果。这件事和交互模式共用 tap、提示符识别和输出整理，所以放在交互模式之后做。

## 七、需要你决定的事

1. **AI 执行命令时，是否屏蔽你的键盘输入？** 建议屏蔽，否则两边的输入会混在一起。
2. **`Bypass` 模式下，高危命令是否仍然要求确认？** 建议仍然确认。
3. **分页的处理方式**：建议自动按空格，因为这不会改动设备上的任何设置。另一种做法是让 AI 先执行 `screen-length disable` 关闭分页，输出更干净，但会改动设备的会话设置。
