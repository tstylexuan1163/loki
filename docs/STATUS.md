### 修掉的两个真 bug

1. **输出丢失**：原先由 store 持有 writer，`TerminalPane` 挂载前收到的数据无人接收，屏幕全黑。
   改为 **pane 自己订阅 `term-event` 并按 sessionId 过滤**，同时在 Rust 侧缓存输出、挂载时 `term_backlog` 取走回放（取走即清空，避免重复）。

## 三、M2：恢复码 / 自动锁定 / 密钥管理 ✅

### 恢复码

创建保险库时生成一次性恢复码（128 位 + 4 字节校验和 → 32 位 Crockford Base32，8 组 × 4）：

```
NHG8 980J ADBD GH83 F8M4 M2BG R8CE MWRF
```

- 只显示一次，必须勾选"已保存"才能进入应用；**本机不保存它**。
- 忘掉密码时用「忘记密码？」→ 输入恢复码即可解开保险库。
- 输入容错：大小写、空格、连字符都不影响；I/L→1、O→0；**U 被拒绝**（避免误认）。
- 校验和让输错一个字符在解密前就被拒绝。

真机验证：创建 → 记录 → 锁定 → 用恢复码解锁 → 进入主界面 ✅

### 自动锁定

- 设置页可选 从不 / 1 / 5 / 15 / 30 / 60 分钟（默认 15）。
- 活动追踪用模块级时间戳，鼠标移动不会触发整个应用重渲染。
- 定时器每 5 秒检查一次；**窗口重新可见时立即检查**，所以合盖休眠后回来不会仍处于解锁状态。
- 锁定时同时断开所有 SSH 会话，并清空内存中的主机明文、终端标签、恢复码。

### 密钥管理

- 生成 Ed25519 / RSA 4096，名称自动带日期，可设注释。
- 列表显示 `SHA256:` 指纹，公钥可一键复制，**私钥从不下发到前端**。
- 私钥与主机凭据一样以密文存进同一张 `items` 表。

真机验证：生成 Ed25519 → 列表显示指纹 ✅

### 修改主密码

设置页可改密码：先验证当前密码，再重新派生。只重新加密保险库密钥，**不重写任何条目**（有测试断言密文逐字节未变），恢复码继续有效。

真机验证：改密 → 旧密码被拒（「主密码错误」）→ 新密码解锁成功 ✅

后端测试：22 个单元测试全绿，覆盖恢复码往返、容错、错位拒绝、错误恢复码被拒、改密不重写条目。

## 四、M3：SFTP + 端口转发 ✅

### SFTP

终端标签上的「文件」按钮打开侧栏，与终端共用同一个 SSH 会话，不额外登录。双击目录进入，双击文件在内置编辑器中打开（4 MB 上限）。

真机验证：列出主目录 → 进入 `.cargo` → 显示真实文件与大小（`env 300 B`、`.global-cache 184.0 KB`）。

集成测试 `sftp_lists_and_round_trips_a_file` 覆盖：写入新文件 → 出现在列表且大小正确 → 读回内容一致 → 重命名 → 删除后消失。

**抓到的 bug**：`SftpSession::write` 只开 `WRITE` 标志，新建文件必然失败（"No such file"）。改成显式 `WRITE|CREATE|TRUNCATE`。

### 端口转发

设置本地端口 → 远端主机:端口，或 SOCKS5。列表显示实际绑定端口，可停止。

真机验证：本地起 HTTP 服务在 18080，转发 `8080 → 127.0.0.1:18080`，`curl http://127.0.0.1:8080/` 返回 **HTTP 200 + 真实 HTML**，界面显示 `本地 · 127.0.0.1:8080 → 127.0.0.1:18080`。

集成测试 `local_forward_carries_traffic` 同样验证 HTTP 响应穿过隧道。

SOCKS5 握手已实现（no-auth + CONNECT），**未做端到端验证**。

终端页「助手」按钮打开侧栏。支持两种协议：**OpenAI 兼容**（OpenAI / OpenRouter / Ollama / LM Studio / vLLM）和 **Anthropic**。设置页有 5 个预设。

### 工具与权限

模型可调用：`read_terminal`、`run_command`、`list_directory`、`read_file`、`write_file`、`grep`。

三种权限模式：

| 模式 | 行为 |

## 六、M5：同步（Worker + D1，仅存密文）✅

`workers/sync/` 是一个可部署到用户自己 Cloudflare 账号的 Worker + D1。

**服务端不做任何加解密**：`envelope` 就是客户端本地已加密的 blob，Worker 只存它和版本号。

| 端点 | 用途 |
|---|---|
| `GET /v1/health` | 探测，含 `initialized` |
| `GET /v1/prelogin` | 取 KDF salt |
| `POST /v1/setup` | 首次初始化（只能一次） |
| `POST /v1/login` | 换 token |
| `GET /v1/items?since=N` | 增量拉取 |
| `PUT /v1/items` | 批量推送 |

冲突规则：按明文 `updated_at` 做 LWW，平局保留服务端版本；服务端强制执行同一规则，过期的推送被拒绝。

会话 token 只存 SHA-256 哈希，D1 被读也无法重放。

### 端到端测试（`tests/sync_live.rs`）

用 Node + SQLite 模拟 D1，验证：

- 条目以密文传输（断言 `prod-api-tokyo`、`10.0.12.31` 不出现在载荷中）
- 拉回的信封**能正确解密**回原始明文
- **过期写入被拒绝**（LWW 生效）

**抓到的 bug**：Worker 与测试服务的 `items` 表都缺 `kind` 列，而客户端需要它区分条目类型——部署后同步会坏。已补齐并贯穿读写路径。

## 七、v0.6.0：界面改造 / Telnet / 串口 ✅

### 1. 日间与夜间模式

`:root[data-theme="light"]` 提供一套暖白配色，强调色降到 `#0f9d6e` 以在白底上保持可读；**终端在两种主题下都保持深色**，因为浅色终端在高对比场景下看不清。

三档：日间 / 夜间 / 跟随系统。选择持久化到本地，`initTheme()` 在首次渲染前执行，窗口不会闪错主题。跟随系统时会监听 `prefers-color-scheme` 变化。

真机验证：设置 → 外观 → 三张带预览的卡片；点「日间」整个界面立即变暖白，主界面层次依然清晰。

### 2. 布局参照 Hatoba

- 侧栏按 Hatoba 分组：**主机 / 端口转发 / 密钥库**，底部是**设置 / 锁定**
- 设置从整页改成**模态窗口**，六个 tab（通用、外观、安全、AI、同步、关于），内容是分组卡片
- 主机列表增加**卡片 / 列表两种视图**和搜索框（搜名称、地址、用户、标签）
- 卡片显示名称、`user@host:port`、标签色块、协议徽章

### 3. Telnet

- 完整 IAC 协商：接受 ECHO / SUPPRESS GA / NAWS，其余一律拒绝（RFC 854 允许）
- `IAC IAC` 还原为字面 0xFF；子协商内容被消费而不上屏
- 连接时先发 NAWS 告知窗口大小
- 与 SSH 共用同一条 `term-event` 通道和同一个终端组件

真机验证：对本地测试服务器连接，屏幕显示 `loki-telnet-test ready` 与提示符，协商字节没有泄漏成乱码。

### 4. 串口

- 用 `serialport` 枚举本机串口（实测列出 4 个设备）
- 波特率 300–230400，数据位 5–8，校验 无/奇/偶，停止位 1/2
- 读取在独立 OS 线程（底层读是阻塞的），写入走 `try_clone` 的句柄
- 同样接进 `term-event` 通道

**尚未真机验证**：串口的实际收发需要真实串口设备或 `socat` 虚拟串口，当前只验证了枚举与打开路径。

### 抓到的三个真 bug

1. **Telnet 被要求提供 SSH 凭据** —— `session_open` 在读主机后立刻构造凭据，导致未保存密码的 telnet 主机报「这台主机还没有保存密码或私钥」。已改成先按协议分派，只有 SSH 才要求凭据。
2. **Telnet 读取空转** —— 协商阶段 `strip_commands` 返回空数组，循环零延迟继续，实测一秒钟跑了几十万次，把 tokio 运行时饿死。空数据时必须 `yield_now()`。
3. **`term_backlog` 只认 SSH 会话** —— telnet/串口的 sessionId 查不到，前端收到错误又被 `.catch(() => {})` 吞掉，表现为终端永远空白。已改为同时查询两个管理器。

### 修掉的 bug

1. **切换标签或页面会清空终端**：之前只挂载当前标签的 xterm，切走就销毁，屏幕和回滚全丢。现在每个标签一个常驻 xterm，非活动的用 `visibility: hidden` 隐藏；终端页本身也常驻挂载。
2. **每次连接都要重新确认指纹**：指纹从未保存。现在存进保险库。
3. **AI 的 `read_terminal` 读到的是登录 banner 而不是当前屏幕**：输出缓冲只存“连接后的前 256 KB”。拆成两块：一次性交给面板的 `pending`，和给助手用的滚动 64 KB `tail`。
4. **`exec_command` 截断输出会 panic**：`String::truncate` 落在多字节字符中间会 panic，中文输出必触发。改为回退到字符边界（有单元测试）。
5. **关闭会话不清理转发和 SFTP 缓存**：现在 `session_close` 一并停止该会话的转发、丢弃 SFTP 通道。
6. **锁定只断开 SSH**：Telnet、串口、本地终端、转发、传输现在都一起关闭，前端标签也同步清空。
7. **自动锁定时间不持久**：每次启动重置为 15 分钟，现在存进本地偏好。
8. **串口回放缓冲无上限**：改为 256 KB 封顶。
9. **主机列表没有删除入口**：API 有但 UI 没有。
10. **PTY 没有下发终端模式**：部分服务器上 Ctrl-C、UTF-8 行编辑异常；现在显式发送 cooked 模式与 `IUTF8`。另加 30 秒 keepalive。

真机验证抓到并已修复的问题：

1. **终端收不到任何实时输出**（严重，旧版就存在）：`TermEvent` 上的 `#[serde(rename_all = "camelCase")]` 只改变体名，不改字段名，后端发的是 `session_id`，前端按 `sessionId` 过滤，所有输出帧都被丢弃。旧版靠回放缓冲把一部分输出补上，问题被掩盖；浏览器模拟环境直接发 `sessionId`，所以也没暴露。加 `rename_all_fields` 并补序列化回归测试。
2. **粘贴的私钥被 macOS “智能破折号”破坏**：`-----BEGIN` 里的连字符被自动替换成 `—`，导致无法解析。后端统一重建 PEM 头尾（也处理 `\r` 和首尾空格），代码类文本框和搜索框关闭拼写检查/自动更正。

4. 串口主机的 `data_bits` / `stop_bits` 在前端读成了 `dataBits` / `stopBits`，编辑时总显示默认值。

仍未在真机窗口里验证：Finder 拖拽上传（需要另外授权访达）、ssh-agent 经 `launchctl` 的路径（集成测试覆盖了 agent 认证本身）、AI 助手（没有配置模型服务商）。

## 九、与蓝图的一致性

实现严格遵循蓝图中的三条硬约束：

1. **秘密单向**：`commands.rs` 的 `HostView` 只暴露 `has_password: bool`，没有任何命令返回密码或密钥。`Vault::encrypt_item` 是唯一出口。导入私钥文件时由 Rust 读取，内容不进 WebView。
2. **只存密文**：`store.rs` 只接受已加密的 `Envelope`；`vault.rs` 的测试 `items_are_encrypted_at_rest` 断言序列化后的密文不含明文。已知主机同样以密文存放。
3. **密文绑定身份**：AAD = `loki/item/v1/{id}`，测试 `item_ids_are_bound_by_aad` 断言把密文挪到另一个 id 下会解密失败。

## 十八、终端导出与会话录制 ✅

计划见 [plans/2026-10-29-next-features.md](plans/2026-10-29-next-features.md) 第 3 项。

### 做了什么

**导出终端内容**
- 标签右键菜单和工具栏「更多」里都有：导出终端内容…、导出选中内容…
- 前端从 xterm 缓冲区取文本（`src/features/terminal/exportText.ts`）：逐行 `translateToString(true)`，
  把 `isWrapped` 的续行拼回同一行，去掉末尾空行；选中内容用 `term.getSelection()`。
- 写入走 Rust 命令 `terminal_export(default_name, text)`：在 Rust 里用 `tauri-plugin-dialog` 弹保存框
  （默认名 `主机名-YYYYMMDD-HHMM.txt`），用户取消返回 null；UTF-8 写入，换行统一为 `\n`。
  **路径只来自原生对话框**，前端不能指定写哪里。

**会话录制**
- 录制在 Rust 的输出管道里做，不在前端拼：SSH 在 `ssh.rs` 读循环 `OutputBuffer::push` 旁边，
  Telnet/串口/本地在 `direct.rs` 的三处 `push_bounded` 旁边；`LiveSession` 和 `direct::Entry`
  各有一个 `Arc<Mutex<Option<Recorder>>>` 槽位。
- `recorder.rs`：`Recorder` 写文件、开头写头信息（目标 / 开始时间 / 模式）、结尾写结束时间。
  **每块写入后立即 flush**（原因见下面「踩到的坑」）。
- 纯文本模式由 `PlainText` 状态机去掉 CSI（颜色、光标）、OSC（标题）、字符集切换（`ESC ( B`），
  CRLF → LF、单独 CR 丢弃；状态跨块保留，被切断的转义序列不会漏进文件。`ESC ( ) * +` 后的
  一个载荷字节也吃掉。
- 命令：`session_record_start(session_id, plain)`（弹保存框后开始）、`session_record_stop`（写尾并关闭）、
  `session_record_status`（路径 / 开始时间 / 已写字节）。
- 会话关闭（`session_close` / `direct_close`）、SSH 远端断开（读循环结束）、锁定保险库
  （`close_everything`）都会结束录制并写尾。
- 界面：录制中的标签有红点，状态栏显示「● 录制中 文件名 · 已写 N KB」，点击即可停止；
  菜单里有「开始录制…」（纯文本）和「开始录制（保留颜色）…」。

### 踩到的坑（已修）

第一版按「每块写入后按时间或大小 flush」实现，结果**录制会在输出停止时丢掉尾部**：
`flush_if_due()` 只在有新数据时被调用，屏幕一安静，最后不到 32 KB 就永远留在 `BufWriter` 里，
文件看起来被截断（实测停在 49676/50000 行）。改成每块写完立即 flush——块本来只有 4–16 KB，
一次 289 KB 的突发写入实测 13 ms，代价可以忽略。

这个 bug 是靠真机测试发现的，单元测试发现不了（单元测试自己会调用 `finish`）。

### 怎么验证的

**单元测试（12 个，全部通过）**：颜色、光标移动、OSC 标题（BEL 与 `ESC \` 两种结尾）、CRLF、
单独 CR、字符集切换、跨块切断的 CSI、跨块 CRLF、退格（含不跨行）、录制器写入头/正文/尾且不含
`0x1b`、原始模式保留控制符、时间戳格式。

**真机测试**（`src-tauri/tests/record_live.rs`，`cargo test --test record_live`，0.24 秒）：
开真实本地 PTY（`LocalPty`），按 `session_record_start` 的方式挂上 Recorder，执行 `seq 1 50000`，
断言：文件 50004 行、包含 1…50000 的每一行、**不含任何 `0x1b` 字节**、结尾有结束行。
这正是验收要求的「录制期间执行 seq 1 50000，停止后 50000 行且不含控制字符」。

**静态检查**：`cargo fmt`、`cargo clippy --all-targets -- -D warnings`（0 警告）、
`cargo test`（97 通过）、`npx tsc --noEmit`、`npx vite build` 全通过。

### 未验证 / 已知限制

- **界面没有逐个点过**：菜单项、红点、状态栏「录制中」都实现并通过类型检查，但这一轮没能可靠地在
  模拟界面里点通（相机环境的窗口坐标反复偏移，几次点到了别的控件上），**没有截图级证据**。
  建议在真实应用里点一遍。
- **导出文件的原生保存对话框没有端到端跑过**：`terminal_export` 里的对话框是原生 API，
  自动化点不动；只验证了编译与命令行逻辑（默认名生成、换行统一、UTF-8 写入）。
- **Telnet / 串口会话的录制只在代码层面对接**：真机测试用的是本地 PTY；真 Telnet 设备和真串口
  仍未实测（串口此前也一直没做过真机验证，见 §九）。
- **纯文本的清洗是「够用」级别**，不是完整终端仿真：退格只能擦掉同一块里刚写入的字符（跨块或
  跨 flush 的擦不掉）；不处理游标定位造成的覆盖（例如用 `\r` 回到行首重写的进度条，只丢弃 CR，
  内容会拼接而不是覆盖）；不处理六线制图形等其他转义。文件末尾、头信息都对得上，正文对「配置
  输出」这类顺序文本是准确的。
- **单一录制**：一个会话同时只能有一个录制，重复开始会报错。

## 二十、AI 附件：附加即上传 ✅（真机验证核心安全属性）

计划见 [plans/2026-10-29-next-features.md](plans/2026-10-29-next-features.md) 第 1 项。这是四项里风险最高的一项，
因为它把本机文件送上服务器，而证书往往和私钥在一起。

### 安全设计（按重要性）

1. **私钥内容永不进入模型上下文**。`redact_private_keys()` 把
   `-----BEGIN … PRIVATE KEY-----` 到 `-----END` 之间的内容替换成「[私钥内容已隐藏]」，
   覆盖 RSA / EC / OPENSSH / ENCRYPTED / 无类型、多个块、缺 END 的截断块、CRLF。
   **所有**工具结果（`run_command` / `read_file` / `grep` / `list_directory` / `read_terminal`）和
   `terminal_tail` 都在 `run_turn` 里统一过这个函数——所以即使模型执行 `cat server.key`，
   它拿到的也是占位符。
2. **按路径拒绝**：`read_file` 读到的是某个 secret 附件的远端路径时，直接返回「这是私钥文件，内容不提供」。
3. **内容不进 WebView**：文件由 Rust 读取，`AttachmentView` 只有 name/size/sha256/kind/secret/remotePath\
   /verified/shareable，**没有内容、没有本机路径**。附件说明由 Rust 拼进用户消息。
4. **secret 判定**看内容不看名字：正文含 `PRIVATE KEY-----` 即 secret（`.key`/`.pem` 因此覆盖），
   `.pfx` / `.p12` / `.jks` 是二进制容器、没有可读标记，按扩展名判定。
5. **上传即同意**：附加文件就是同意传到这台服务器，不再二次确认；但后续改动服务器的命令仍走原有权限模式
   （`may_run_unattended`），没有新增任何“上传/执行”工具。
6. 暂存目录 `~/.loki/uploads/<批次>/` 逐级 700，文件先写 `.part` 再改名、权限 600，并**在服务器上
   `sha256sum`（或 `shasum -a 256`）比对**，不一致就如实 `verified: false`，不假装成功。

### 行为

- 回形针按钮（多选）或把文件拖到助手面板；非 SSH 标签回形针置灰，提示「仅 SSH 连接支持附件」。
- 输入框上方是附件卡片：文件名、大小、远端路径（可复制）；secret 显示锁图标与「私钥内容不会发给 AI」；
  `verified=false` 显示警告；shareable（文本、非私钥、≤64 KB）有「让 AI 看到内容」开关（默认开）；可移除。
- 用户气泡里显示本次附带的文件（仅名称/大小）。
- 面板底部一行「服务器上有 N 个暂存文件 · 清理」，确认后删掉整批。
- 移除**尚未发送**的附件会同时删服务器上的文件；已发送过的保留（模型已知路径）。
- SFTP 面板文件右键「发给 AI」：把远端路径用反引号包好插入助手输入框（走一个 zustand 单槽，
  不用 window 事件）。
- 历史会话保存附件元数据（name/size/sha256/remotePath/secret），不保存内容。

### 怎么验证的

单元测试（`src/ai/attach.rs`，12 个）：kind 判定；secret 判定（内容命中 / 扩展名 / 证书不算）；
每种 PEM 类型都被抹掉；多块 + CRLF；缺 END 时隐藏其后全部；证书与公钥不受影响；批次名格式；
shell 转义（含 `'`）；**附件说明即使被误塞了私钥内容也不会输出**；可分享文件带内容与大小。

真机测试（`tests/attach_live.rs`，对临时的本机 sshd `127.0.0.1:2222` 运行，2 个用例通过）：
- 上传脚本 → 远端哈希一致（`verified=true`）、`stat` 权限 **600**、没有残留 `.part`、
  `sh run.sh` 输出 `attach-ok-42`、`remove_tree` 能删掉整个批次。
- 上传 `server.key`（含 `SUPERSECRETKEYBODY31337`）→ 服务器上确实有（`cat` 能读出来），
  而经过 `redact_private_keys`（即 `run_turn` 对每个工具结果所做的事）后**正文消失**。
  这就是「包括 AI 执行 cat 私钥之后」那条验收。

静态检查：`cargo fmt`、clippy（0 警告）、`cargo test`（118 通过）、`npx tsc --noEmit`、`npx vite build`。

### 未验证 / 已知限制

- **界面没有逐点点验**（和前两项同样的自动化环境问题）：回形针、附件卡片、拖放、暂存清理行、
  「发给 AI」都只做了类型检查与构建。**尤其是拖放**依赖 `getCurrentWebview().onDragDropEvent`，
  浏览器模拟里没有 Tauri 通道，无法在 mock 里演示；原生打开对话框同理。
- **`ai_detach` 未发送即删文件**只做了代码对接，没有真机用例（它需要 `AppState`，集成测试拿不到）。
- **`read_file` 的路径比对是字面比较**：模型若用 `~/.loki/...` 之外的形式（例如展开后的绝对路径）
  就不会命中那条快速拒绝——不过 `redact_private_keys` 仍然兜底，内容照样会被抹掉。
- 只支持单个 SSH 会话内的暂存；换会话看不到上一批文件。锁定时附件表清空（服务器上的文件保留，
  需要手动清理或在下次清理）。
- 单文件 20 MB、一次 10 个上限是硬编码常量（`ai::attach`），没有做成设置项。

## 二十一、审查后的修复（附件 / 录制 / 历史）✅

审查第十七至二十节的实现后修复的问题：

- **附件路径在后续轮次丢失**：历史消息只带用户文字，第二句起模型不知道文件在哪。现在每条带附件的
  用户消息在重建历史时附上「名称、大小、远端路径」（私钥只给路径），内容不重复发送。
- **切换标签后附件串到另一台服务器**：助手面板跨标签复用，待发送附件不会清空。现在切换会话时移除
  未发送的附件（同时删除服务器上的副本），暂存文件计数按会话分开；`ai_send` 也拒绝属于其他会话的附件。
- **私钥路径保护只在附加那一轮有效**：`secret_paths` 现在取该会话登记过的全部私钥附件；
  `read_file` 的比对兼容 `~/.loki/…`、多余的 `/` 和 `./`（新单元测试）。同一批次目录不再重复登记。
- **锁定后附件卡片残留**：锁定时一并清空。
- **录制纯文本处理不了分页**：改成按行缓冲、带光标的模型——`\r` 回到行首覆盖、`\b` 左移、
  `ESC[nD/C/G` 移动、`ESC[K` 清行、`ESC[P/X/@` 编辑，换行时写出并去掉行尾空格。
  Cisco `--More--`（`\r` + 空格 + `\r`）和华为/H3C `---- More ----`（`ESC[42D` + `ESC[K`）
  都不再残留；进度条只保留最后状态；跨块的 UTF-8 字符能正确拼回（新单元测试）。
  `tests/record_live.rs`（本地 shell 跑 `seq 1 50000`）照常通过。
- **每次保存对话都解密全部历史**：清理旧对话改为只看行的类型和更新时间，不再解密。
- **保存对话可能覆盖其他记录**：`ai_conversation_save` 先检查同 id 的现有记录，类型不是对话就拒绝。
- 模拟界面：新保存的对话出现在历史列表；回形针在 mock 里返回一对证书/私钥用于演示。
- **附件上传进度是假的**：原来整个文件一次写完，写完后才连发 0/60/100%。现在按 256 KB 分块写入，
  按实际写入字节汇报进度（每秒最多十次，结束时一次）；到 100% 后卡片显示「校验中…」，
  服务器端哈希校验完成才消失。`tests/attach_live.rs` 新增 3 MiB 分块上传用例，校验哈希一致、
  进度单调并以 (总量, 总量) 结束。

验证：`cargo fmt`、clippy（0 警告）、`cargo test`（126 个单元测试 + 集成测试通过）、
`npx tsc --noEmit`、`npx vite build`；mock 界面用 Playwright 验证了附加 → 第二轮历史带路径、
切换标签后附件移除并调用 `ai_detach`、历史列表出现新对话。

### 未验证 / 已知限制

- `tests/attach_live.rs` 三个用例在本机测试 sshd（127.0.0.1:2222）上通过；没有在远程 Linux 服务器上测试。
- 录制按行写出：还没换行的最后一行（比如提示符）要等下一行或停止录制时才写入文件。
- 纯文本模式把宽字符（中文）当一个格，用光标移动回删中文时可能多删或少删。
- 私钥过滤只认 PEM 块：`base64`、`xxd`、`openssl rsa -text` 这类输出拦不住。
  在“每次确认”模式下执行前会先看到命令。

## 二十二、登录弹窗、可选用户名、Windows 菜单卡顿 ✅（Windows 未实机验证）

用户反馈（Windows）：弹窗里输入密码一直提示不对，同样的密码保存到主机后能连；不填用户名无法保存主机；
点击菜单偶尔卡顿、有残影。

- **弹窗输入的密码优先**：`credentials_for` 原来在主机已存密码时会忽略弹窗输入的密码，
  继续用旧的已存密码。现在输入的密码替换已存密码（单元测试）。在 macOS 上没能复现"同一密码弹窗失败"，
  所以弹窗加了能自查的手段：**显示密码**按钮（Enter 仍然是登录）、**大写锁定**提示、
  **中文/全角字符**提示（输入法在中文状态时 `!` 会变成 `！`）；重试时如果服务器给的不是
  "密码被拒绝"，把真实原因显示出来。Edge/WebView2 自带的密码显示按钮在这个输入框里隐藏，避免出现两个。
- **用户名可以留空**：主机编辑页不再要求用户名，占位提示"留空则连接时询问"。连接时如果没有用户名，
  `session_open` 返回 `needUsername`，终端弹出"输入用户名"，默认勾选"登录成功后保存到主机"；
  之后的密码弹窗、重连都沿用这个用户名。跳板机没有用户名时直接报错说明。`login_name` 有单元测试。
- **Windows 菜单卡顿和残影**：在 mock 里用 4 倍 CPU 降速测量导航、"更多"菜单、标签右键菜单，
  都没有长任务，问题不在 JS。WebView2 下常见的原因是整块区域的 `backdrop-filter` 模糊，
  以及带大阴影的弹出层做 transform 动画。现在 Windows 上去掉遮罩模糊（遮罩稍微加深），
  菜单、对话框、提示、查找栏等弹出层只做 80ms 淡入；macOS 不变。系统开启"减少动态效果"时不做动画。

验证：`cargo fmt`、clippy（0 警告）、`cargo test`（128 通过）、`npx tsc --noEmit`、`npx vite build`；
mock 新增一台没有用户名的主机 `nas`，Playwright 走通 用户名 → 密码（错误重试、显示密码、全角提示）→ 连接；

## 二十八、长对话的长度控制 ✅（已被第二十九节取代）

问题：每次提问都把整段对话（含每条命令的输出，单条最多 30,000 字符）重新发给模型。聊到二三十条命令后，
一次请求就有几百 KB，变慢、变贵，最后超过模型的上下文上限直接报错。

- 新增 `src-tauri/src/ai/context.rs`，每轮开始前把历史压到预算内（约 48,000 token，按中文一字一 token、
  其他约 3.5 字符一 token 估算），不额外调用模型：
  1. 最近 2 轮的命令输出完整保留（单条超过 12,000 字符时保留头尾）；更早的输出只保留头尾共 1,200 字符，
     并注明「需要完整内容可以重新执行」。
  2. 仍超预算时从最早的一轮开始整轮丢弃（一轮 = 一个问题到下一个问题之间的全部消息，工具调用和结果不会被拆开），
     最新一轮永远保留，并在第一个保留的问题前告诉模型更早的内容没有发送。
- 新事件 `context`（被丢弃的轮数、精简的输出数、估算 token、预算）。`AiEvent` 加上
  `rename_all_fields = "camelCase"`，并有测试保证字段名到前端是驼峰。
- 面板：被精简的那次回复下面显示「为控制长度：N 段命令输出已精简，更早的 M 轮对话未发送」；
  估算超过预算 60% 或已经丢弃过内容时，输入框上方建议「开新对话」并给出按钮。
- 只影响发给模型的内容，保存的对话记录和界面上显示的输出都不变。

验证：`cargo test`（新增 8 个：估算、短对话原样、旧输出精简与新输出保留、超长新输出截断、整轮丢弃并告知、
工具结果不与调用分离、单轮永不丢弃、事件字段驼峰）、clippy、`npx tsc --noEmit`、`npx vite build`；
mock 连续问 4 次，第 3、4 次出现精简说明和「开新对话」提示，点击后清空。

### 未验证 / 后续
- 预算是固定值，没有按模型区分。Ollama 等本地模型默认上下文常只有 8K，可能仍会超；后续可以在服务商设置里加「上下文长度」。
- 没有用模型做摘要（会多一次调用）；现在是机械精简。

## 二十九、按模型的上下文长度控制，自动识别上限 ✅

第二十八节用固定预算（约 48,000 token），而且不管多长都精简较早的输出。两个问题：大上下文模型（例如 1M）根本不需要精简；
精简改动了对话前面的内容，会让服务商的前缀缓存失效（模型接口每次都要发送整段对话，靠缓存让重复的开头便宜又快）。
改为：

- **平时不精简。** 只有知道模型上限、且对话超过它（留出回复、系统提示和 10% 估算余量，`budget_for`）时才精简：
  先从最早的命令输出开始截短，再截短最近的，最后整轮丢弃最早的对话（最新一轮永远保留），只截到够用为止。
- **上限从哪里来（不需要手填）：**
  1. 服务商的模型列表写了就用：OpenRouter `context_length`、vLLM `max_model_len`、LM Studio `max_context_length` 等
     （`provider::context_of`）。在服务商对话框「获取模型列表」时记录；没记录过的模型在每次运行第一次提问时查一次。
     OpenAI、DeepSeek 的列表不提供这个数。
  2. **超长报错时学习并自动重试**：识别 OpenAI 兼容接口（含 DeepSeek、vLLM）和 Anthropic 的超长报错（`is_overflow`），
     从报错里读出上限（`limit_from_error`，如「maximum context length is 65536」「200000 maximum」），记住到这个服务商的这个模型，
     精简后重试；报错里没有数字时按本次大小的 2/3 估计；最多重试两次，第二次再收紧到 70%。
  3. 手动设置降为服务商对话框里的可选项（默认折叠，留空 = 自动），对该服务商所有模型生效，优先于自动识别。
- 上限保存在服务商的加密记录里（`context_limit` 手动、`context_limits` 按模型自动），编辑服务商时自动识别的值保留。
- 面板：学到上限并重试时显示「这个模型的上下文上限是 X token（服务商在报错中给出，已记住），已精简后自动重试」；
  真的精简过时显示精简了什么，并在输入框上方建议开新对话（显示「已用 / 上限」）。服务商对话框里每个模型旁边显示识别到的上下文长度。

验证：`cargo test`（新增：预算计算、未超限时原样发送、超限时只截最早且够用即止、整轮丢弃、工具结果不与调用分离、
单轮只截不丢、超长报错识别、从报错读上限、模型列表读上限、按模型记住且手动优先；以及一个端到端测试：本地假模型服务器
第一次返回「maximum context length is 32768」，第二次正常回复，断言学到 32768、精简、重试成功，重试请求不到第一次的一半）、
clippy、`npx tsc --noEmit`、`npx vite build`；mock 里检查了重试提示、接近上限提示和服务商对话框。

### 未验证 / 已知限制
- 没有对真实的 DeepSeek / Claude 制造超长请求来确认报错原文；识别规则按公开的报错格式写，并保留了「看不到数字就估计」的退路。
- Ollama 超长时通常不报错，而是悄悄截掉开头，所以学不到上限；用 Ollama 的小模型建议在服务商里手动设置上下文长度。
- 估算按字符数近似，代码和英文多的内容可能偏差；用服务商返回的实际用量校准留作后续。
- 还没有给 Anthropic 请求加缓存标注（Claude 需要显式标注才走缓存价）。

## 三十、停止 AI 回复，关闭标签不再卡住 ✅

问题：AI 回复不能中途停止；回复里有一步命令在等确认时关闭那个标签，后台会一直等这个确认，
而「同一时间只跑一个回复」会让所有标签的 AI 都卡住，只能重启；锁定时类似，旧回复的结束信号还可能把新回复错标为结束。

- 后端：`ai::run_cancellable` 用 `select!` 包住整个回复，停止时直接丢弃——不管是在等模型、等确认还是在执行命令——
  并发出 `stopped` 事件。每次回复有编号（`turnId`，前端生成），所有事件都带上它。新命令 `ai_cancel(turnId?)`；
  开始新回复时先停掉还在跑的旧回复；锁定（`close_everything`）也会停止；回复结束时只清理属于自己的状态，不碰新回复的。
- 前端：回复进行中，发送按钮变成「停止」；被停止的回复标注「已停止」，没执行的步骤显示删除线和「未执行」，确认按钮不再出现
  （从历史打开、当时没执行完的步骤也这样显示）。事件按编号过滤，旧回复的残留事件不会影响新回复。
  关闭正在回复的标签会自动停止它，其他标签马上可以提问。

验证：`cargo test`（新增：等模型时能在 2 秒内停止并发出 `stopped`；等确认时能停止且命令没有执行；`stopped` 事件格式）、
clippy、`npx tsc --noEmit`、`npx vite build`；mock 里验证：流式输出中途停止后不再增长、按钮恢复；等确认时停止，
确认按钮消失、步骤显示「未执行」；等确认时关闭标签，另一个标签没有「另一个标签正在执行」的提示，并能正常提问和收到回复。
