## Fixes / 修复

**A saved API key stays with its server / 已保存的密钥只发给原服务器**
- Editing a provider and leaving the key blank keeps the saved key only while the base URL is on the
  same server (scheme, host and port). Before, pointing a provider at another host and clicking
  "test connection" or "fetch model list" sent the old key to that host. The dialog now warns when
  the saved key will not be reused.
- 编辑服务商时密钥留空，只有新地址仍是同一台服务器（协议、主机、端口相同）才沿用已保存的密钥。
  此前把地址改到别的主机再点「测试连接」或「获取模型列表」，旧密钥会被发到新地址。
  现在对话框会提示“地址换了服务器，请重新填写密钥”。

**Base URLs are used as typed / 基础 URL 按填写原样使用**
- `/v1` is now added only to providers saved by 0.7. It used to be added to any URL not ending in a
  version, which broke endpoints such as Gemini's OpenAI-compatible `…/v1beta/openai`.
- 只有 0.7 保存的旧服务商才会自动补 `/v1`。此前凡是不以版本号结尾的地址都会被补上，
  导致 Gemini OpenAI 兼容端点 `…/v1beta/openai` 这类地址无法使用。
